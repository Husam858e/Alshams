# تقسيم الملف — مع بقاء ملف واحد للنشر

`wheelmanagement_v17_promax_40.html` يبقى **الملف الوحيد الذي يُنشر**: تنسخه إلى
Netlify كما هو، بلا بناء ولا حزم ولا خطوة وسيطة. هذا لم يتغيّر ولن يتغيّر.

ما أُضيف هو نسخة **مقروءة** منه في `src/` — نفس البايتات مقسّمة إلى ٣٧ ملفاً
حسب الأقسام. الفائدة عملية بحتة:

- تفتح `src/js/18-cash.js` (٥٢٠ سطراً) بدل التنقّل في ملف من ١٨٨٥٦ سطراً
- `git log src/js/15-pay.js` يريك تاريخ الدفع وحده
- الاختلافات في المراجعة تُنسب إلى القسم الذي تخصّه

## الملف الواحد هو المصدر — لا العكس

هذه نقطة الأمان الأساسية. لو صار `src/` هو المصدر لأصبح كل نشر رهينة سكربت
بناء، ولو أخطأ السكربت مرّة واحدة لخرجت أرقام خاطئة إلى نظام حسابات حقيقي.
فالاتّجاه الافتراضي معكوس:

```
wheelmanagement_v17_promax_40.html  ──(npm run split)──►  src/
```

تعدّل الملف الواحد كالمعتاد، ثم `npm run split` ليلحق `src/` به.

الاتجاه الآخر متاح للطوارئ (تعديل وحدة بعينها ثم إعادة التجميع):

```
src/  ──(npm run build -- --write)──►  wheelmanagement_v17_promax_40.html
```

## الأوامر

| الأمر | ما يفعله |
|---|---|
| `npm run split` | يعيد توليد `src/` من الملف الواحد، ويرفض إن لم تُعِد الأجزاء تركيب الأصل بايتاً ببايت |
| `npm run build` | يتحقّق فقط: هل تجميع `src/` يطابق الملف الواحد؟ يخرج بخطأ إن لا |
| `npm run build:write` | يجمّع `src/` ويكتب الملف الواحد فعلاً |
| `npm run verify` | `build` ثم كل مجموعات الاختبار |

## لماذا يستحيل أن يفسد التقسيم الملف

ثلاثة أقفال، لا واحد:

1. **التجميع نسخ بايتات لا غير.** لا تصغير، لا إعادة ترتيب، لا تحويل ترميز.
   `assemble()` في `tools/parts.js` يقرأ الأجزاء ويصلها بأسطر جديدة — انتهى.
2. **`split.js` يرفض عمله إن لم يطابق.** يقسّم، ثم يعيد التجميع فوراً، ويقارن
   بالأصل. عدم التطابق يعني خروجاً بخطأ وبقاء الملف كما هو.
3. **`tests/t_build.js` جزء من `npm test`.** يفشل إن تأخّرت `src/` عن الملف،
   أو صارت مرساة غير فريدة، أو وقع قطع داخل دالة أو نصّ.

## كيف تُحدَّد الحدود

في `build/manifest.json`. كل جزء يُعرَّف بـ **سطر مرساة** — سطر كامل فريد في
الملف — لا برقم سطر:

```json
{ "file": "src/js/18-cash.js", "anchor": "   الخزينة — v17.52", "back": 1 }
```

`back: 1` تعني أن القطع يقع سطراً واحداً قبل المرساة، أي عند خط الزينة
`/* ══…` الذي يعلو العنوان، فيبقى العنوان مع قسمه.

أرقام الأسطر تتغيّر مع كل تعديل؛ عناوين الأقسام لا تتغيّر. ولهذا يشترط
`cutPoints()` أن تكون كل مرساة **فريدة تماماً** في الملف: مرساة مكرّرة تعني
قطعاً غامضاً، والغموض يوقف الأداة بدل أن يُخمّن.

### إضافة قسم جديد

1. اكتب القسم في الملف الواحد كالعادة، تحت خط زينة وعنوان.
2. أضف مدخلاً في `build/manifest.json` في موضعه من الترتيب.
3. `npm run split` — إن اشتكى من مرساة غير فريدة، غيّر نصّ العنوان.
4. `npm test`.

## لماذا هذه الحدود بالذات

كل حدّ نقطة **مستوى أعلى** في الـ JS: لا داخل دالة ولا نصّ ولا قالب. تحقّقنا
من ذلك بتشغيل `node --check` على كل جزء وحده — وهو ما يفعله `t_build.js` في كل
تشغيل. لو انزلق حدّ يوماً إلى داخل دالة، سيسقط الاختبار قبل أن يصل شيء إلى
الإنتاج.
